# Design Specification: The Craftsman & TDD Pipeline

**Document ID:** `docs/designs/002_craftsman_tdd_pipeline.md`  
**Status:** Approved  
**Author:** Elephant Agent & Developer  
**Target Milestone:** Milestone 3 (v1.4.0)  

---

## 1. Overview & Objectives

This specification defines the architectural design for **Milestone 3 (v1.4.0)** of `artifice`: establishing the dedicated Code Authoring Agent (`code-author` — "The Craftsman"), codifying the specification-driven Test-Driven Development (TDD) workflow with model-attributed commits, hardening the EGM contract handoff bridge (`scripts/validate_egm.py`), and formalising the Front-Loaded "Grill-Me" Interview Protocol in `spec-egm`.

### Goals

* **The Craftsman Agent Persona:** Introduce `agents/code-author/agent.md` ("The Craftsman") as the pragmatic, contract-first implementation counterpart to The Gatekeeper (`code-reviewer`) and The Catalyst (`developer-coach`).
* **Contract-First TDD Lifecycle:** Codify an unambiguous implementation sequence: Ingestion $\rightarrow$ Red (failing invariant assertions) $\rightarrow$ Green (minimal deterministic logic) $\rightarrow$ Refactor (Occam's Razor slimming) $\rightarrow$ Pre-Review Baseline Gate.
* **Model Author Attribution:** Ensure all Git commits generated during the authoring cycle explicitly identify the authoring model and agent persona in the Git commit metadata and trailers (`Co-authored-by:` / `Model-Author:`).
* **Hardened EGM Bridge (`validate_egm.py`):** Add targeted specification validation (`--spec <id_or_path>`) to `scripts/validate_egm.py`, enabling automated verification gates that block implementation subagents from proceeding if specifications are unapproved or incomplete.
* **Front-Loaded "Grill-Me" Protocol:** Formalise Step 1A of `skills/spec-egm/SKILL.md` to mandate a structured interrogation of architectural trade-offs, non-goals, failure fallbacks, and model tiering before drafting technical specifications, maximising unattended continuous autonomy.

### Non-Goals

* **Autonomous Merging to `main`:** Autonomous branch commits and PR drafting are permitted on feature branches, but direct pushes to `main` and formal merge approval remain strictly human (`[HUMAN]`).
* **Unbounded Local Generation:** Local coding models (`qwen2.5-coder:14b` or `codestral:22b`) are restricted to bounded boilerplate and algorithmic helper micro-passes; overall architectural coordination and PR drafting remain on frontier models.

## 2. Domain Framing & User/System Experience

The system establishes an explicit division of labour across the software development lifecycle:

1. **Architectural Alignment & Scoping:** The developer and agent conduct Step 1A (Empirical Recon & Grill-Me Workshop). Ambiguities, trade-offs, and failure modes are resolved upfront.
2. **Contract Specification:** The Elephant drafts `docs/designs/<NNN>_<feature>.md`, subjected to an adversarial zero-context review by the Goldfish (`docs/reviews/<NNN>_<feature>_review.md`).
3. **Automated Bridge Verification:** Before authoring code, `validate_egm.py . --spec <NNN>` is invoked. If non-zero, execution halts immediately with actionable errors.
4. **Craftsman Implementation:** `code-author` takes the approved specification, writes failing tests first, commits the test suite with model attribution, implements minimal code, verifies green tests, commits the implementation with model attribution, and verifies the repository's native lint and test baseline (`./scripts/lint.sh`).
5. **Gatekeeper Review:** Once the baseline is 100% green, `code-reviewer` performs an advisory 8-Pillar audit before human PR sign-off.

## 3. State Schema & Data Models

### Git Commit Provenance & Trailer Schema

Every commit generated by an implementation agent or model must adhere to the Conventional Commits standard and append structured provenance trailers:

```text
<type>(<scope>): <concise description in British English>

<detailed narrative body explaining the invariant or contract fulfilled>

Model-Author: <PRIMARY_ENGINE_OR_MODEL> (e.g. Gemini 3.8 Flash)
Agent-Role: code-author (The Craftsman)
Co-authored-by: <PRIMARY_MODEL> (<CLIENT_HARNESS>) <<HANDLE>@artifice.local>
Co-authored-by: <OFFLOADED_MODEL> <<MODEL_REF>@ollama.local>
```

> [!NOTE]
> GitHub exclusively parses `Co-authored-by: Name <email>` trailers to display contributor avatars and co-author attribution in its web interface and PR diffs. Structured trailers like `Model-Author` and `Agent-Role` provide provenance auditability in Git logs, but any contributing model must be included in a `Co-authored-by` trailer to render on GitHub.

### Targeted Spec Validation CLI Contract (`validate_egm.py`)

```text
Usage:
  python3 scripts/validate_egm.py <repo_root> [--spec <spec_id_or_path>]

Arguments:
  <repo_root>              Path to target repository (default: current directory).
  --spec <id_or_path>      Optional specific design specification to validate.
                           Accepts numeric prefix (e.g. '002', '2') or filename
                           (e.g. '002_craftsman_tdd_pipeline.md').

Exit Codes:
  0: Specification valid, required sections present, and matching Goldfish
     review possesses 'Verdict: Approved'.
  1: Missing sections, unapproved review, or missing specification file.
```

## 4. Invariants & Rules

* **Invariant 1 (Specification Precedence):** Implementation code or subagent dispatch is strictly prohibited until the target specification passes `validate_egm.py --spec <id>` with exit code `0`.
* **Invariant 2 (Contract-First Red Phase):** Authoring agents must write failing tests exercising contract invariants before writing production code. Tests must be executed and empirically confirmed failing before feature logic is introduced.
* **Invariant 3 (Model Commit Authorship):** Every commit created by automated authoring tools or models must include explicit model provenance (`Model-Author` and `Co-authored-by` git trailers) to preserve transparent attribution in the Git log.
* **Invariant 4 (Pre-Review Baseline Gate):** No authoring subagent or workflow may request Gatekeeper review (`review`) or draft a PR without first running the repository's native test and lint suites (`./scripts/lint.sh`) locally to confirm a 100% green baseline.
* **Invariant 5 (Host Memory Stewardship):** Any authoring wave that leases local Ollama models (`local-code`) must invoke `scripts/check_ollama.py unload --all` upon wave completion to restore the host memory footprint to 0MB.
* **Invariant 6 (British English & Markdown Cleanliness):** All generated code comments, commit messages, documentation, and agent output must be strictly in British English, with blank lines following every Markdown heading.

## 5. Execution & State Mutation Logic

### 1. Step 1A: Empirical Recon & Grill-Me Workshop

1. The orchestrator runs empirical disk recon (git status, baseline health, existing types).
2. The orchestrator conducts an interactive Grill-Me interview interrogating the author across:
   * Architectural options and non-goals.
   * State schemas and data invariants.
   * Model tiering and local offloading boundaries.
   * Test strategies, mutation probes, and failure recovery.
3. The developer confirms alignment before any specification is drafted.

### 2. Step 1B & Step 2: Specification & Goldfish Critique

1. The Elephant authors `docs/designs/<NNN>_<feature>.md` with required sections.
2. A zero-context Goldfish reviewer audits the specification against repository rules and produces `docs/reviews/<NNN>_<feature>_review.md`.
3. Revisions continue until `Verdict: Approved` is signed off.

### 3. Step 3: Hardened Bridge Gate

1. The orchestrator executes `python3 scripts/validate_egm.py . --spec <NNN>`.
2. If validation fails, execution halts with a diagnostic report detailing missing sections or unapproved status.

### 4. Step 4: The Craftsman Implementation Cycle (`code-author`)

1. **Ingest Contracts:** Ingest the approved specification and run `scripts/build_review_dossier.py` to capture invariants.
2. **Red Phase:**
   * Author boundary tests asserting Section 4 and Section 7 specifications.
   * Execute test suite natively; verify non-zero exit code due to missing feature logic.
   * Commit tests using Conventional Commits with model trailers:
     `git commit -m "test(<scope>): assert invariant contracts for spec <NNN>" ...`
3. **Green Phase:**
   * Write minimal sufficient logic. If generating repetitive mock fixtures or algorithmic transforms, optionally delegate micro-passes to `local-code` (Ollama `qwen2.5-coder:14b` or `flash`).
   * Execute test suite natively; verify zero exit code (all tests passing).
   * Commit implementation with model trailers:
     `git commit -m "feat(<scope>): implement deterministic logic for spec <NNN>" ...`
4. **Refactor Phase:**
   * Prune dead code, redundant wrappers, and verify Core Diet limits.
   * If altered, commit refactoring with model trailers.
5. **Local Baseline Gate:**
   * Execute `./scripts/lint.sh` and repository test suites.
   * If any failure occurs, repair locally before proceeding.

### 5. Step 5: Gatekeeper Pre-Flight Review

1. Dispatch `code-reviewer` (`review`) to conduct an 8-Pillar advisory audit.
2. Draft PR via `gh pr create` with advisory review attached.

## 6. Edge Cases & Failure Modes

* **Target Spec Not Found in `validate_egm.py --spec`:** Script prints available specifications, returns exit code `1`, and blocks subagent dispatch.
* **Review Marked 'Revisions Required':** `validate_egm.py --spec` detects that verdict is not `Approved`, outputs the review findings, and halts handoff.
* **Red Phase Tests Pass Prematurely:** If boundary tests pass before implementation code is written, the tests are tautological or test existing behaviour. The authoring agent must halt and revise test assertions to properly exercise the new contract.
* **Local Ollama Model Offline During Authoring:** `local-code` detects offline engine and falls back instantaneously to cloud `flash`, preserving continuous execution.
* **Multi-Model Authoring Contribution:** If Gemini architects the code and Qwen synthesises a helper function, both models are attributed in the Git commit trailers (`Model-Author: Gemini 3.8 Flash`, `Co-authored-by: Gemini 3.8 Flash (Antigravity) <antigravity@artifice.local>`, `Co-authored-by: Qwen 2.5 Coder 14B <qwen2.5-coder@ollama.local>`).

## 7. Verification & Automated Test Strategy

### Functional & Governance Verification

* **Static Governance Linters (`./scripts/lint.sh`):**
  * Asserts Markdown cleanliness across all files.
  * Validates YAML frontmatter syntax for skills and agents (`agents/code-author/agent.md`).
  * Enforces Core Diet ceilings ($\le 140$ lines for `AGENTS.md`, $\le 180$ lines for `SKILL.md`).
  * Validates relative links across documentation and skill assets.
* **EGM Contract Validation (`scripts/validate_egm.py`):**
  * Directly verifies that all active specifications possess required sections and approved Goldfish reviews.
  * Validates targeted specification checks (`--spec <id_or_path>`).
