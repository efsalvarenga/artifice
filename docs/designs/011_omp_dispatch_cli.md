## Overview

`omp-dispatch` is a zero-dependency Python 3 command-line dispatcher (`scripts/omp-dispatch` + `scripts/omp_dispatch.py`) paired with a mounted skill (`skills/omp-dispatch/SKILL.md`) that lets Google Antigravity (`agy`, running Gemini) offload four bounded, context-heavy workloads to a local `omp` (`oh-my-pi` v18.22.0) CLI installation running Mistral (`mistral/mistral-large-latest` with `--thinking high`) on the same machine sharing repository directories.

### Terminology

* **`agy` (Antigravity CLI):** The stateful primary coding agent ("Elephant") running on Gemini, responsible for interactive conversation, design drafting, finding resolution, test and lint verification, Git branching, GitHub App bot-authored commits, and Pull Request operations.
* **`agy` harness primitives & config layout:** `run_command` executes shell commands (using `BypassSandbox: true` to run outside the terminal sandbox (Antigravity's sandboxed shell for `run_command`), `WaitMsBeforeAsync` to background long jobs, and `NotificationTimeoutSeconds` for delayed wakeup notifications); `"Always Allow"` denotes Antigravity's persistent command-prefix approval rule in its UI; `invoke_subagent` spawns native Gemini subagents; and `${GEMINI_HOME:-$HOME/.gemini}/config/` holds Antigravity configuration files including optional personal `mcp_config.json` and persistent daemon `sidecars/`.
* **`omp` (`oh-my-pi`) & CLI flags:** A separate local coding agent CLI installed on the same host (tested on `v18.22.0`), run headlessly via `omp -p` (non-interactive print mode), `--model <id>` (target model identifier), `--thinking <level>` (reasoning effort), `--cwd <path>` (working directory), and stateless isolation flags (`--no-session --no-skills --no-rules --no-context-files --no-extensions --no-lsp --no-pty`) so host sessions and repo `AGENTS.md` files never leak into zero-context passes. `@<prompt_path>` loads prompts from disk to avoid `MAX_ARG_STRLEN` (the Linux ~128 KiB single-argument size cap); `--tools=<allowlist>` restricts tools per run; `--approval-mode=write` auto-approves only file edits (`edit`, `write`), unlike `yolo` which permits unattended shell execution.
* **EGM (Elephant-Goldfish Model) & review scopes:** The upstream [google/elephant-goldfish-model](https://github.com/google/elephant-goldfish-model) plugin (metadata manifest `<egm_dir>/plugin.json`, baseline `v0.1.1`, commit `270b103`, per [design 006](006_externalise_egm_plugin.md)) split into stateful **Elephant** orchestration (`egm-brainstorm`, `egm-review`, and interactive finding resolution `egm-resolve`) and zero-context **Goldfish** review lenses (`egm-brainstorm` Step 2 and `egm-review` Stages 5–9, culminating in Stage 9 Implementation Readiness). Document standards are per-lens evaluation rubrics under `<egm_dir>/resources/document_standards/`. `TargetFile` (`--target <design.md>`) names the reviewed specification; `full` scope passes the entire `TargetFile`; `FeatureRange` (`--feature-range <start>-<end>`, 1-based inclusive line numbers) covers architectural sections; `DetailedRange` (`--detailed-range <start>-<end>`, 1-based inclusive line numbers) covers the implementation plan; `GoldfishContext` is the verified list of context file paths supplied via repeatable `--context-file <path>` flags; stage scope labels (`full`, `feature+detailed`, `feature`, `full+stage5`, `detailed`) select which ranges accompany a stage prompt.
* **Occam's Razor 4-lens review:** Artifice's default Pull Request and code review procedure in [skills/review/SKILL.md](../../skills/review/SKILL.md), which evaluates bundled verbatim artefacts tagged with trace ID `pr-<N>-<head-sha8>` (`head-sha8` is the first 8 hexadecimal characters of the PR head commit SHA) across four read-only lenses (`egm-zoom-out`, `egm-design`, `egm-codebase-details`, `egm-comprehension`).
* **Core Diet & canonical word budget:** Artifice's anti-bloat governance limits enforced by [scripts/lint.py](../../scripts/lint.py) (`SKILL.md` ≤180 lines / 1,000 words; `agent.md` ≤900 words) and [tests/test_artifice.py](../../tests/test_artifice.py) (`≤3,750-word` shared ceiling across the canonical agent and skill files enumerated in that test's `test_live_repository_and_canonical_word_budget`, measured via `len(text.split())`).
* **Repository privacy markers (`Privacy: on-device`, `Review: local-only`):** Repository-level opt-out directives placed in `AGENTS.md` (and scanned upward to the repository root by [scripts/mistral_ocr.py](../../scripts/mistral_ocr.py)'s `policy_blocks_hosted`) indicating that repository contents must stay on-device rather than egressing to hosted APIs.
* **GitHub App bot identity & provenance:** Dedicated agent Git/GitHub authentication (`scripts/github_app_auth.py`, `scripts/gh-bot`, [design 010](010_github_app_bot_identity.md)) and mandatory commit trailers (`Model-Author`, `Agent-Role`, `Co-authored-by`) validated by [scripts/validate_provenance.py](../../scripts/validate_provenance.py) per [rules/global-agents.md](../../rules/global-agents.md).

## The Problem

When using `agy` as the primary interactive orchestrator for specification design, implementation, and review, four bounded workloads multiply Gemini context consumption because each spawns isolated contexts that ingest full design documents, codebase reading lists (`GoldfishContext`), or Pull Request diffs:

1. **`egm-brainstorm` Step 2** fans out 7 parallel Goldfish brainstorm lenses.
2. **`egm-review` Stages 5–9** executes up to 10 Goldfish reviewer dispatches across five review stages.
3. **Occam's Razor PR/code review** ([skills/review/SKILL.md](../../skills/review/SKILL.md)) spawns 4 parallel read-only review lenses over bundled raw artefacts.
4. **Spec-driven code implementation** reads an approved Stage 9 EGM technical specification and iteratively writes implementation and test files across multiple turns.

After [design 008](008_vibe_shrink_review_gh_posting.md) retired `scripts/vibe_execute.py` and `skills/vibe-execute/` (leading to `README.md:137`'s deferred hosted-Mistral clause), `artifice` has no hosted-Mistral offload path left. Meanwhile, running `omp` ad hoc from `agy` fails on operational friction: `~/.local/bin` is absent from non-login subshell `PATH`, large inline prompts exceed `MAX_ARG_STRLEN`, `omp --max-time` exits `0` on timeout (masking failed lenses as clean), and granting shell execution inside headless `omp` re-introduces a `yolo` approval surface (all four documented in https://github.com/efsalvarenga/artifice/issues/28), while live Antigravity testing on this host (`2026-11-26`) also hit `EROFS` (read-only file system errno) on `~/.omp` and blocked network egress inside `agy`'s terminal sandbox.

Issue https://github.com/efsalvarenga/artifice/issues/28 previously declined a broad thin-orchestrator pattern where `agy` delegated general coding sessions to `omp`, because `agy`'s main conversation history kept growing with no meaningful Gemini savings. Narrowing delegation strictly to these four isolated workloads changes the trade-off: `agy` keeps interactive Elephant orchestration, shell verification, Git operations, and PR posting, while `omp` absorbs the heavy subagent fan-out and file-editing tokens on Mistral and returns only out-of-tree report paths plus a bounded summary.

## Goals

* **Four bounded CLI workloads plus preflight health:** Provide `scripts/omp-dispatch` (thin Bash wrapper) and `scripts/omp_dispatch.py` (Python 3 stdlib core) exposing five subcommands — `brainstorm`, `egm-review`, `occam-review`, `implement`, and `health` — defaulting to `mistral/mistral-large-latest` with `--thinking high` (parameterised and overridable per call), reducing offloaded `brainstorm` Step 2, `egm-review` Stages 5–9, and `occam-review` passes to `0` native Gemini `invoke_subagent` calls.
* **Dual granularity for `egm-review` Stages 5–9:** Allow the caller to select at invocation time either stage-by-stage execution (default, preserving interactive `egm-resolve` edits and checkpoint gates in `agy`) or an uninterrupted Stages 5–9 batch with deterministic fail-fast handling.
* **Strict tool isolation and zero `yolo` shell surface:** Run all three review/brainstorm workloads with read-only tools only (`--tools=read,grep,glob`), and run spec-driven code implementation (`implement`) strictly with file read/edit tools (`--tools=read,grep,glob,edit,write`, `--approval-mode=write`, no `bash`). `agy` retains all test/lint execution (`./scripts/lint.sh`, `unittest`), repair loops, Git branching, bot-authored commits, and PR operations.
* **Write-boundary checks and provenance:** Validate pre-flight repository-root path confinement inside a required Git working tree, acquire a per-repository exclusive lockfile, and perform post-run worktree scope detection (over `--ignored` paths, `HEAD` revision, external-symlink escapes even within `allowed_rel` (the allowlist of repo-relative paths a run may modify, defined under Write-Boundary Checks), and Git hooks/config metadata, excluding runner-owned run/log artifacts) before releasing the lock on `implement` runs — pre-flight validation plus post-run detection-before-commit rather than OS-level prevention — attribute bot commits of `omp`-written code to `Model-Author: mistral/mistral-large-latest` (validated by [scripts/validate_provenance.py](../../scripts/validate_provenance.py)), and tag `occam-review` traces with `--producer omp` (`"requires_elephant_verification": true`) so Mistral lenses never silently self-certify.
* **Mechanical reliability, observability, and aligned timeouts:** Enforce real Python wall-clock timeouts with process-group termination (`start_new_session=True`, `os.killpg`), align the per-lens review timeout at `600 s` across `omp-dispatch` and [skills/review/SKILL.md](../../skills/review/SKILL.md) (with `900 s` default for `implement`), cap parallel workers at `1..4` (`DEFAULT_MAX_WORKERS = MAX_WORKERS_LIMIT = 4`), retry failed or timed-out lenses at most once with uniform jittered backoff, return machine-readable status enums (`ok | retried-ok | not-run-timeout | not-run-failed`), write full raw reports out-of-tree, and append one sanitised JSONL metric record per completed or failed lens call to gitignored `.omp-dispatch-log.jsonl`.
* **Zero personal-config mutation and Core Diet compliance:** Leave `~/.gemini/config/mcp_config.json` and all personal user files untouched (preserving issue https://github.com/efsalvarenga/artifice/issues/23), keep `skills/omp-dispatch/SKILL.md` within Core Diet limits (≤180 lines / 1,000 words enforced by [scripts/lint.py](../../scripts/lint.py), targeting ≤100 lines / ≤500 words to leave headroom), update the canonical word ceiling in [tests/test_artifice.py](../../tests/test_artifice.py) for the seventh canonical file, and keep `./scripts/lint.sh` and `python3 -m unittest discover -s tests -p 'test_*.py'` at exit code `0`.
* **Explicit governance alignment:** Update https://github.com/efsalvarenga/artifice/issues/65 to reflect the reversed `agy` → `omp` `omp-dispatch` scope and record the scoped supersession of https://github.com/efsalvarenga/artifice/issues/28 and `README.md` (`## Model Dispatch Surface (retired)`, heading line 135, deferred hosted-Mistral clause line 137).
* **Privacy markers refuse by default:** every workload pre-flight runs the `policy_blocks_hosted` upward `AGENTS.md` scan from `<repo_root>` ([scripts/mistral_ocr.py](../../scripts/mistral_ocr.py)); on `Privacy: on-device` / `Review: local-only` the run refuses with `exit 2` (`"error": "privacy_marker_refusal"`) unless `--allow-hosted-egress` is passed for that invocation, and each override is logged with its `trace_id` to `.omp-dispatch-log.jsonl` — the standing waiver (https://github.com/efsalvarenga/artifice/issues/66#issuecomment-7214588390) now covers only [skills/review/SKILL.md](../../skills/review/SKILL.md)'s harness-native fan-out pending https://github.com/efsalvarenga/artifice/issues/66.

## Non-Goals

* **No Stdio MCP server or Antigravity `sidecar.json` daemon:** No JSON-RPC 2.0 server framing, no async `start`/`poll`/`cancel` job store, and no writes to `~/.gemini/config/mcp_config.json` or `~/.gemini/config/sidecars/`.
* **No reverse (`omp` → `agy`) bridge:** Reverses https://github.com/efsalvarenga/artifice/issues/65's initial draft; `omp` does not invoke `agy`.
* **No stateful Elephant phases inside `omp`:** `omp-dispatch` does not draft or edit design specifications, does not run interactive `egm-brainstorm` Steps 1/3/4, `egm-review` Stages 1–4, or `egm-resolve`.
* **No `bash`, Git, or GitHub operations inside `omp`:** Branch creation, test/lint execution, commits, pushes, and PR creation/commenting remain exclusively in `agy`.
* **No change to the privacy gate in mounted `artifice` skills:** audit and removal of the `Privacy: on-device` / `Review: local-only` gate across mounted skills remain tracked in https://github.com/efsalvarenga/artifice/issues/66; `omp-dispatch` itself refuses by default (see Goals) with only a per-invocation, logged `--allow-hosted-egress` override.
* **No Copilot or `omp`-host mounting changes:** Verified on Linux; macOS untested (uses POSIX `fcntl` and `os.killpg`); `scripts/install_copilot.sh` and `scripts/install_omp.sh` remain unchanged.

## Open Questions

* None. Architectural, transport, naming, permission, timeout, privacy-waiver, and governance decisions are resolved from design discussions, maintainer triage, and live host benchmarks (2026-11-26 brainstorm and 2026-11-27 review runs).

## Critical User Journeys (CUJs)

### CUJ 1: Offloading `egm-brainstorm` Step 2 to `omp`

* **Given**: An `agy` session has completed Step 1 clarification and holds an anchored feature concept (the Step 1 clarification brief from `/egm-brainstorm`) on a host with `omp` and the upstream EGM plugin installed.
* **When**: `agy` invokes `scripts/omp-dispatch brainstorm` (backgrounded outside the terminal sandbox via `run_command`) with the concept file, repository root, and trace ID.
* **Then**: `omp_dispatch.py` runs all 7 upstream EGM brainstorm lenses with read-only tools (`--tools=read,grep,glob`), max 4 concurrent workers, and a `600 s` per-lens wall-clock timeout; writes the full raw lens reports to the out-of-tree cache directory; appends sanitised entries to `.omp-dispatch-log.jsonl`; and returns a bounded JSON summary with per-lens statuses and report paths so `agy` can synthesise `concepts_brief.md` (the consolidated Step 2 brainstorm brief) without spawning Gemini subagents.

### CUJ 2: Offloading `egm-review` Stages 5–9 (Stage-by-Stage or Batch)

* **Given**: An `agy` session has completed `egm-review` Stages 1–4 (`TargetFile`, `FeatureRange`, `DetailedRange` in `<start>-<end>` 1-based inclusive line format, and `GoldfishContext` file paths resolved).
* **When**: The user chooses either a single stage (`5`, `6`, `7`, `8`, or `9`, default mode) or the `5-9` batch, and `agy` runs `scripts/omp-dispatch egm-review`.
* **Then**: `omp_dispatch.py` dispatches the exact upstream EGM Goldfish lenses for the requested stage(s) (enforcing Stage 6's zero-`GoldfishContext` self-containment rule). In `5-9` batch mode, if all lenses in any stage finish `not-run-*`, remaining stages abort immediately with `"partial": true`; if Stage 5's `egm-zoom-out` fails to produce a report, Stage 8 is recorded as `not-run-failed` (`error: "stage5 report unavailable"`) rather than running degraded. Raw reports stay out-of-tree and structured statuses plus paths return to `agy` for `egm-resolve` or consolidation.

### CUJ 3: Offloading 4-Lens Zero-Context Occam's Razor PR Review

* **Given**: An `agy` coordinator has bundled verbatim PR artefacts (metadata, commits, exact diff, linked issues treated as data, optionally prepared via [scripts/build_review_dossier.py](../../scripts/build_review_dossier.py)) and trace ID `pr-<N>-<head-sha8>` per [skills/review/SKILL.md](../../skills/review/SKILL.md).
* **When**: `agy` runs `scripts/omp-dispatch occam-review` (passing `--producer omp` whenever the diff contains `omp`-written code).
* **Then**: `omp_dispatch.py` runs the four read-only lenses (`egm-zoom-out`, `egm-design`, `egm-codebase-details`, `egm-comprehension`) with zero coordinator conversation history, tags the trace/reports with `trace_id` (and sets `producer=omp` / `"requires_elephant_verification": true` when applicable), and returns machine-readable statuses plus out-of-tree report paths. If any lens finishes as `not-run-timeout` or `not-run-failed` after 1 retry, `agy` treats the review as partial and blocks sign-off; when `"requires_elephant_verification": true`, `agy` records explicit Elephant/human verification before sign-off.

### CUJ 4: Spec-Driven Code Implementation Without `bash` (Phase 2 — gated on #68)

* **Given**: A design document has passed Stage 9 (or human sign-off), `agy` has checked out the implementation branch inside a Git working tree, and the target file paths within the repository are known.
* **When**: `agy` invokes `scripts/omp-dispatch implement` with the verbatim approved specification path, target file paths, and optional failure trace on a repair pass.
* **Then**: `omp_dispatch.py` verifies `<repo>` resides inside a Git working tree (standard clone or linked worktree), confirms every target path resolves inside the repository root, acquires the per-repository lockfile, runs `omp` with `--tools=read,grep,glob,edit,write` and `--approval-mode=write` (`900 s` default timeout, no `bash`), runs post-run worktree-status metadata inspection (including gitignored files, `HEAD` revision, symlink-escape checks even in `allowed_rel`, and resolved Git `config`/`hooks` metadata, excluding runner-owned run/log artefacts) without diff bodies while still holding the lock, releases the lockfile, and returns a bounded summary (`agy` owns post-flight detection enforcement before verification or commit). `agy` then runs `./scripts/lint.sh` and `unittest` inside its sandbox, sends back only compact failure traces if a bounded repair pass is needed, and creates bot-authored commits crediting `Model-Author: mistral/mistral-large-latest` validated by [scripts/validate_provenance.py](../../scripts/validate_provenance.py).

### CUJ 5: Timeout, Failure & Preflight Diagnostics

* **Given**: A missing `omp` binary, missing upstream EGM persona file, Mistral API rate limit (`429`), a privacy marker (`Privacy: on-device` / `Review: local-only`) in an upward `AGENTS.md` without `--allow-hosted-egress`, or a lens exceeding its `600 s` wall-clock timeout.
* **When**: `agy` runs `scripts/omp-dispatch health` or any workload subcommand.
* **Then**: `health` reports resolved `omp` path/version and EGM plugin persona availability with classified exit codes using precedence `127 > 2 > 124 > 1 > 0` (`127` if missing `omp`, `2` on invalid config/persona failure). During workloads, transient failures or timeouts trigger a process-group kill (`os.killpg`), persist partial stdout/stderr alongside the report directory, retry at most once with uniform jittered backoff (honouring numeric `Retry-After` headers up to `120 s`), and on exhaustion report `not-run-timeout` (exit `124`) or `not-run-failed` (exit `1`).

## Technical Plan (Architecture)

`omp-dispatch` is composed of a thin Bash entrypoint (`scripts/omp-dispatch`), a Python 3 stdlib core runner (`scripts/omp_dispatch.py`), and a mounted Antigravity skill (`skills/omp-dispatch/SKILL.md`). No MCP server, background daemon, or personal configuration file write is involved.

### System Data Flow

```text
agy (Elephant, Gemini)
  ├─ Interactive EGM Stages 1–4, egm-resolve, design edits
  ├─ Sandboxed verification (./scripts/lint.sh, python3 -m unittest)
  └─ Git branches, bot commits (github_app_auth.py + validate_provenance.py), gh-bot PRs
         │
         │ run_command (BypassSandbox: true, WaitMsBeforeAsync: 5000,
         │              NotificationTimeoutSeconds per skills/omp-dispatch/SKILL.md;
         │              non-blocking wakeup hint — re-wait until process exit)
         ▼
scripts/omp-dispatch  ──►  scripts/omp_dispatch.py (stdlib Python 3)
                             ├─ 1. Validate args, trace-id, ranges/stage5-report, repo, out-dir, EGM files
                             ├─ 2. For implement: Git working-tree check, path confinement,
                             │      flock lockfile, pre-run status/HEAD/hooks snapshot
                             ├─ 3. Create run_dir (0700), prune stale/finished, assemble prompts (@file)
                             ├─ 4. ThreadPoolExecutor (max_workers: 1..4)
                             │      └─ omp -p --no-session --no-skills --no-rules
                             │            --no-context-files --no-extensions
                             │            --no-lsp --no-pty --cwd <repo_root>
                             │            --model mistral/mistral-large-latest
                             │            --thinking high --tools=<allowlist>
                             │            (own process group; Python timeout + killpg;
                             │             max 1 retry with uniform jitter / Retry-After cap)
                             ├─ 5. For implement: post-run audit_scope (HEAD + symlink escape +
                             │      --ignored + hooks/config, excluding runner run_dir/log), release flock
                             ├─ 6. Write full raw reports + summary.json to cache (0700)
                             ├─ 7. Append sanitised entry per lens to .omp-dispatch-log.jsonl
                             └─ 8. Print identical bounded JSON summary to stdout
```

### Component Boundaries

1. **Bash Wrapper (`scripts/omp-dispatch`):** Mirrors [scripts/gh-bot](../../scripts/gh-bot)'s `python3 -c` `os.path.realpath` shim on `"${BASH_SOURCE[0]}"` and runs `exec python3 "$SCRIPT_DIR/omp_dispatch.py" ${1+"$@"}`. Providing a single executable path gives Antigravity a prefix-matchable command shape for "Always Allow" approvals outside the terminal sandbox.
2. **Core Python Runner (`scripts/omp_dispatch.py`):** Uses Python 3 standard library only (`argparse`, `concurrent.futures`, `fcntl`, `hashlib`, `json`, `os`, `pathlib`, `random`, `re`, `shutil`, `signal`, `subprocess`, `sys`, `time`, `typing`, `uuid`). Handles environment hygiene (prepending `~/.local/bin` to `PATH`), `@file` prompt materialisation (avoiding `MAX_ARG_STRLEN`), `1..4` worker range validation, process-group timeout cleanup, retries, Git working-tree and path confinement, `--out-dir` containment checks, lockfiles, sanitised logging, cache retention, and bounded JSON output.
3. **Mounted Skill (`skills/omp-dispatch/SKILL.md`):** Concise runbook within Core Diet limits (≤180 lines / 1,000 words enforced; ≤100 lines / ≤500 words headroom target) instructing `agy` when and how to invoke each subcommand with `BypassSandbox: true`, `WaitMsBeforeAsync: 5000`, and concrete `NotificationTimeoutSeconds` wakeup hints (`900` single-stage / `occam-review`; `1050` `implement`; `1500` multi-wave `brainstorm` / `egm-review --stage 5-9`, noting worst-case single-lens `429`-retry wall clock reaches `~1320 s` and aggregate worst case reaches ≈2,100 s for `brainstorm` / ≈3,000 s for `egm-review --stage 5-9` (7–10 lenses × up to 2 attempts × 600 s on 4 workers), so `agy` must re-wait until process exit on early wakeup notifications), summary-first preview consumption (only redacted `preview` strings may reach GitHub comments), partial/`not run` blocking, mandatory Elephant verification when `"requires_elephant_verification": true`, the bounded repair loop for `implement` (max 2 repair passes in `agy`), avoiding ad-hoc invocations in repos declaring `Privacy: on-device` / `Review: local-only`, and commit provenance.
4. **Review Skill Alignment (`skills/review/SKILL.md`):** Raises the documented per-lens timeout budget on line 40 from `300 s` to `600 s` so native execution (subject to host harness limits) and `omp-dispatch` (mechanically enforced by Python) share one timeout policy; keeps line 36's harness-native `invoke_subagent` spawn as default with a concise parenthetical cross-reference permitting `agy` coordinators to offload the 4 read-only lenses via `omp-dispatch occam-review`; and preserves line 38's explicit per-PR human approval rule before hosted fan-out while https://github.com/efsalvarenga/artifice/issues/66 remains open.

### Subcommand Contracts

All subcommands share common options: `--repo <path>` (default `.`), `--trace-id <id>` (auto-generated UTC timestamp + 8-hex UUID when omitted; required for `occam-review`; validated across workloads against `TRACE_ID_PATTERN` `^[A-Za-z0-9][A-Za-z0-9._-]{0,127}$` failing fast with `exit 2` on invalid characters or path separators, supporting both `pr-<N>-<head-sha8>` PR traces and arbitrary local/branch review tags), `--model <id>` (default `mistral/mistral-large-latest`), `--thinking <level>` (default `high`), `--timeout <seconds>` (default `600` for review/brainstorm, `900` for `implement`), `--max-workers <1..4>` (default `4`; values outside `1..4` fail fast with exit `2`), `--egm-dir <path>` (default `${GEMINI_HOME:-$HOME/.gemini}/config/plugins/egm`), `--out-dir <path>` (overrides cache run dir; rejected with exit `2` if equal to or inside `<repo_root>` unless gitignored), `--omp-bin <path>` (overrides binary lookup), and `--allow-hosted-egress` (store-true; overrides the privacy-marker refusal for this invocation only, appending an audit record to the JSONL log).

| Subcommand | Required Inputs | Optional / Stage-Required Inputs | `omp` Tool Allowlist & Approval | Default Timeout |
| --- | --- | --- | --- | --- |
| `brainstorm` | `--concept-file <path>` | shared flags | `--tools=read,grep,glob` | `600 s` / lens |
| `egm-review` | `--target <design.md>`, `--stage <5\|6\|7\|8\|9\|5-9>` | Stage-required (`exit 2` if missing): `--feature-range <start>-<end>` (Stages `6`, `7`, `5-9`), `--detailed-range <start>-<end>` (Stages `6`, `9`, `5-9`, 1-based inclusive), `--stage5-report <path>` (standalone Stage `8`); Optional: `--context-file <path>` (repeatable) | `--tools=read,grep,glob` | `600 s` / lens |
| `occam-review` | `--trace-id <id>`, `--artefact <path>` (repeatable) or `--bundle-dir <dir>` | `--producer <human\|agy\|omp>` (default `human`; author provenance — `omp` sets `requires_elephant_verification: true`, `human`/`agy` keep `false`) | `--tools=read,grep,glob` | `600 s` / lens |
| `implement` | `--spec <design.md>`, `--target-file <rel>` (repeatable) | `--failure-file <path>` | `--tools=read,grep,glob,edit,write --approval-mode=write` | `900 s` / pass |
| `health` | none | `--egm-dir`, `--omp-bin` | read-only preflight (`omp --version` + plugin check) | `15 s` |

#### Exact Upstream EGM Stage & Lens Mapping

Personas are read verbatim (YAML frontmatter stripped) from `<egm_dir>/agents/` and document standards from `<egm_dir>/resources/document_standards/`:

### Process Hygiene, Timeout & Retry Semantics

1. **Deterministic prompt assembly & process isolation:** Every run writes `<run_dir>/prompt_<key>.md` containing sections (a)–(e) in fixed order: (a) stripped persona text from `<egm_dir>/agents/<persona_filename>` (omitted for `implement`), (b) document standard from `<egm_dir>/resources/document_standards/<standard_filename>` when non-`None`, (c) structured metadata header (`Mode`, `Stage`, `Reviewer Lens`, `trace_id`, `TargetFile` / `Active Scope`, plus `Producer: omp (same-family review — requires Elephant/human verification)` when `--producer omp`), (d) workload payload (`--concept-file`, line-numbered scoped `TargetFile` excerpt, untrusted-data-framed PR artefacts/dossier, or `--spec` + declared `--target-file` list + optional `--failure-file`), and (e) supplemental context (`GoldfishContext` except Stage 6, plus `--stage5-report` on Stage 8). `omp_dispatch.py` then invokes `omp` with `@<prompt_path>` followed by the trailing CLI instruction as separate argv elements (eliminating `MAX_ARG_STRLEN` failures). Every `omp` subprocess launches with `--no-session --no-skills --no-rules --no-context-files --no-extensions --no-lsp --no-pty` so host sessions, profiles, and repo `AGENTS.md` files never leak into zero-context lenses or contend on `~/.omp/agent/sessions`.
2. **Process-group timeouts (working around `omp --max-time`):** Each child spawns with `start_new_session=True` (creating its own process group; `os.killpg` covers the PGID, but a `setsid` detach cannot be ruled out against closed-source `omp` internals, so the runner additionally sweeps surviving descendants via a `/proc` PPID-walk — see `reap_descendants`). `omp_dispatch.py` enforces the wall-clock deadline in Python rather than trusting `omp --max-time` (which https://github.com/efsalvarenga/artifice/issues/28 observed exiting `0` on timeout). On expiry, the runner sends `SIGTERM` to the child process group (`os.killpg`), waits up to `5 s`, then sends `SIGKILL`, calls `reap_descendants(pid)` to kill any `/proc` PPID-walk survivors that escaped the PGID via `setsid`, persists any partial stdout/stderr to `<run_dir>/partial_<key>.log`, and records exit code `124`. Parent `SIGTERM`/`SIGINT` handlers iterate all active child PGIDs and terminate them so no `omp` process outlives its caller.
3. **Bounded retry with backoff:** A lens that times out, exits non-zero, or produces empty stdout is retried at most once after uniform jittered backoff (`5–10 s`, increasing to `15–25 s` if stderr indicates HTTP `429` rate limiting; when stderr includes a numeric `Retry-After` value on `429`, sleep `min(120.0, max(jittered_backoff, retry_after))`). Non-retryable configuration errors (missing binary `127`, invalid arguments/paths `2`) fail fast without retry.
4. **Machine-readable status enum:** Every lens entry reports one of four statuses: `ok`, `retried-ok`, `not-run-timeout`, or `not-run-failed`. A timed-out or failed lens is never reported as zero findings. If any lens finishes in a `not-run-*` state, the top-level JSON sets `"partial": true` and `agy` blocks sign-off until retried or explicitly waived by the human.

### Write-Boundary Checks & Provenance (`implement`)

1. **Git working-tree check & pre-flight path confinement:** `implement` requires `<repo>` to reside inside a Git working tree (`git -C <repo_root> rev-parse --is-inside-work-tree`, covering both standard clones and linked worktrees; `exit 2` outside Git). `omp_dispatch.py` resolves `repo_root = os.path.realpath(repo)`. Every `--target-file` is normalised relative to `repo_root` and verified via `os.path.realpath` to stay strictly inside `repo_root` (rejecting empty paths, absolute paths outside the repo, `..` traversal, symlink escapes, or `.git/` paths). If `--spec` appears in `--target-file`, the runner rejects the invocation (exit `2`) so `omp` cannot alter the specification it is implementing. Because `omp` runs with `--tools=read,grep,glob,edit,write` without OS-level filesystem write enforcement, confinement plus step 4 below act as pre-flight declaration validation and post-run repo detection-before-commit rather than kernel-level prevention.
  2. **Exclusive per-repository lockfile:** Before launching `omp`, `implement` acquires a non-blocking exclusive `fcntl.flock` lock on `${XDG_CACHE_HOME:-$HOME/.cache}/artifice/omp-dispatch/locks/<sha256(repo_root)[:16]>.lock` (opened with `O_CREAT`; after acquiring, `fstat` verifies the inode and re-opens/re-locks on mismatch, so a cache cleaner deleting/recreating the file cannot let two runs hold different inodes), holding it through `omp` execution and the post-run scope audit before releasing. This blocks concurrent `omp-dispatch implement` runs against the same repository (`exit 2` with `"error": "lockfile_contended"` immediately on contention). `agy` must not edit repository files while an `implement` pass is active — stated explicitly in `skills/omp-dispatch/SKILL.md`; the Python lock cannot cover `agy`'s own edits.
3. **Non-shell tool isolation:** `implement` runs `omp` strictly with `--tools=read,grep,glob,edit,write --approval-mode=write`. `bash` is absent from `--tools`, eliminating shell execution and `yolo` approval risk.
4. **Post-run scope audit & recovery:** Before spawning `omp`, `omp_dispatch.py` snapshots `git -C <repo_root> status --porcelain -z --ignored`, `".git-meta/HEAD"` (`git -C <repo_root> rev-parse --verify HEAD`, `"UNBORN"` if no commit yet), and metadata `(mtime_ns, size)` for the worktree's resolved Git config and hooks paths (`git -C <repo_root> rev-parse --git-path config` and `--git-path hooks`, resolved via `os.path.realpath` and keyed under canonical synthetic keys `".git-meta/config"` and `".git-meta/hooks/<rel>"` so linked worktrees whose common gitdir lies outside `repo_root` work identically to standard clones). After `omp` finishes and before releasing `fcntl.flock`, it takes the same snapshot (running every audit `git` call with `-c core.hooksPath=/dev/null` and `GIT_CONFIG_NOSYSTEM=1` so a tampered hook cannot fire during detection), checks every changed/created worktree entry — **even when listed in `allowed_rel`** — to verify it is neither a symlink (`os.path.islink`) nor resolved outside `repo_root` (`os.path.realpath`), and compares all modified/created keys against `allowed_rel` (declared `--target-file` paths plus runner-owned repo-relative paths: `<run_dir>` subtree if `--out-dir` sits inside `repo_root`, and `<repo_root>/.omp-dispatch-log.jsonl` if gitignored). Any symlink escape, `HEAD` mutation, or change outside `allowed_rel` sets `"scope_violation": true`, lists unexpected paths in `"unexpected_paths"`, and exits `1`. On `scope_violation`, `omp_dispatch.py` intentionally leaves the worktree dirty rather than auto-reverting files so `agy` or the user can inspect unintended edits; `agy` checks `git status` and reverts or deletes unexpected changes before retrying or committing.
5. **Commit provenance & anti-self-review:** `agy` remains the sole committer using GitHub App bot auth ([design 010](010_github_app_bot_identity.md)). Commits containing code authored by `omp-dispatch implement` record `Model-Author: mistral/mistral-large-latest` (or the actual `--model` used), `Agent-Role: code-author`, and legitimate `Co-authored-by` trailer(s), validated via [scripts/validate_provenance.py](../../scripts/validate_provenance.py) before commit. Subsequent `occam-review` passes over those diffs pass `--producer omp`, stamping the same-family warning into report headers and setting `"requires_elephant_verification": true` in summary JSON.

### Output Envelope, Exit Codes, Logging & Cache Retention

* **Bounded stdout JSON envelope:** Full raw Markdown reports stay on disk; stdout emits structured metadata plus a short sanitised preview (≤400 characters per lens), byte-identical to `<run_dir>/summary.json`. Note that `summary.json` and stdout JSON are **local-caller metadata only** (they retain raw local paths in `run_dir` and `report_path` so `agy` can read reports directly, whereas `preview` and `.omp-dispatch-log.jsonl` are sanitised) and must never be pasted verbatim into GitHub PR or issue comments; only redacted short `preview` strings (or separately sanitised summaries) may reach GitHub comments:

```json
{
  "workload": "brainstorm",
  "trace_id": "20261126T203000Z-a1b2c3d4",
  "producer": "human",
  "requires_elephant_verification": false,
  "model": "mistral/mistral-large-latest",
  "thinking": "high",
  "partial": false,
  "scope_violation": false,
  "unexpected_paths": [],
  "run_dir": "/home/user/.cache/artifice/omp-dispatch/runs/20261126T203000Z-...",
  "total_elapsed_s": 204.23,
  "results": [
    {
      "lens": "egm-design",
      "stage": null,
      "status": "ok",
      "attempts": 1,
      "exit_code": 0,
      "elapsed_s": 104.0,
      "bytes": 8616,
      "report_path": ".../report_egm-design.md",
      "stderr_path": null,
      "preview": "1. Major — ...",
      "error": null
    }
  ]
}
```

* **Classified exit codes (coarse classifier, precedence `127 > 2 > 124 > 1 > 0`):** `127` = `omp` binary not found; `2` = CLI/env usage error (`--max-workers` outside `1..4`, malformed `--trace-id`, non-integer/`< 1` `OMP_DISPATCH_MAX_RUNS`, malformed or missing stage-required line range / `--stage5-report`, non-Git working tree on `implement`, `--out-dir` non-ignored inside repo, path confinement refusal, lockfile contention `"error": "lockfile_contended"`, privacy-marker refusal `"error": "privacy_marker_refusal"` without `--allow-hosted-egress`, or failed `health`/stage EGM check); `124` = one or more lenses ended `not-run-timeout`; `1` = partial pass (`not-run-failed`) or `scope_violation`; `0` = all lenses `ok`/`retried-ok` with zero `scope_violation`. Detailed per-lens state remains in JSON `partial`, `scope_violation`, `results`, and `error` (disambiguating `exit 2` CLI vs operational causes).
* **Out-of-tree report directory & retention:** Defaults to `${XDG_CACHE_HOME:-$HOME/.cache}/artifice/omp-dispatch/runs/<timestamp>-<trace_id>/` (created `0700` only after up-front validation succeeds so `exit 2` creates no directory), outside Git-tracked paths and paths scanned by [scripts/lint.py](../../scripts/lint.py). If `--out-dir` resolves equal to or inside `<repo_root>`, it is rejected with exit `2` unless covered by `git -C <repo_root> check-ignore -q`. At run start, the runner parses `OMP_DISPATCH_MAX_RUNS` (default `50`; fail fast with exit `2` on non-integer or `< 1`) and prunes the oldest prunable run directories (directories containing `<run_dir>/summary.json`, or unfinished directories whose mtime is older than `DEFAULT_STALE_RUN_S = 7200` seconds so concurrent cross-repo in-flight runs stay protected while crashed runs are reaped, excluding `active_dir`) beyond that limit.
* **Sanitised JSONL log (`.omp-dispatch-log.jsonl`):** Following [design 009](009_ship_it_issue_to_pr_pipeline.md)'s `.ship-it-log.jsonl` guard, `omp_dispatch.py` checks `git -C <repo_root> check-ignore -q .omp-dispatch-log.jsonl`; if ignored (added to `artifice`'s `.gitignore` in Phase 2, Target File 8), it appends one sanitised JSON line per completed or failed lens call to `<repo_root>/.omp-dispatch-log.jsonl`; otherwise it falls back to `${XDG_CACHE_HOME:-$HOME/.cache}/artifice/omp-dispatch/omp-dispatch-log.jsonl` so consuming repositories stay clean. Every log record sanitises `$HOME` / `/home/<user>` to `~` and strips `file://` and `conversation://` links (matching [design 008](008_vibe_shrink_review_gh_posting.md)). A granted `--allow-hosted-egress` override appends one extra sanitised record (`"event": "hosted_egress_override"` plus `trace_id` and the detected marker list) so per-call consent stays auditable.
* **Preflight `health` & up-front EGM checks:** Workload subcommands validate only the EGM persona and document standard files required by the invoked workload/stage (`exit 2` if missing). `health` verifies `omp` binary resolution and `omp --version`, checks `<egm_dir>/plugin.json` and `git -C <egm_dir> rev-parse HEAD` against tested baseline `v0.1.1` (`270b103`, emitting a warning on drift rather than failing), and verifies readability of all brainstorm, `egm-review` Stages 5–9, and `occam-review` EGM files (`exit 2` if missing). `health` also reports the `policy_blocks_hosted` scan result for `<repo_root>` (marker list or `none`) without refusing.

## Alternatives Considered

### Alternative A: Python Stdio MCP Server (`scripts/omp_mcp.py`)

* **Pros**: Exposes typed JSON-schema tools directly inside `agy` and runs outside `agy`'s terminal sandbox without `BypassSandbox: true` prompts.
* **Cons**: Official Antigravity MCP documentation (https://antigravity.google/docs/mcp.md, lines `159–189`) enforces a default 3-minute (`180 s`) per-tool-call timeout (`MCP tool call to server "..." timed out after 3m0s`), raisable only via `timeoutSeconds` in `~/.gemini/config/mcp_config.json` (which re-opens [design 005](005_shared_governance_and_commit_provenance.md) and [design 007](007_unified_harness_mounting.md)'s unmanaged personal-config boundary recorded in https://github.com/efsalvarenga/artifice/issues/23). Under the default `180 s` ceiling, while the brainstorm run (`204.23 s` aggregate) kept every individual lens under `180 s` (`max 146.40 s`), Stage 6 `egm-comprehension` peaked at `328.77 s` on a single lens — forcing either personal `mcp_config.json` mutation or an async `start`/`poll`/`cancel` state machine with polling turns and hand-rolled JSON-RPC 2.0 framing.
* **Reason for Rejection**: Rejected by author (2026-11-26), tracked in https://github.com/efsalvarenga/artifice/issues/65: `agy`'s `run_command` already provides native background execution and reactive wakeup with no `180 s` default ceiling, zero protocol code, and zero personal-config mutation.

### Alternative B: Antigravity Persistent `sidecar.json` Background Daemon

* **Pros**: Antigravity supervises process startup and restarts automatically via `~/.gemini/config/sidecars/<id>/sidecar.json`.
* **Cons**: `sidecar.json` is built for background daemons and cron schedules, not callable agent tools; reaching it from `agy` would require building and securing a local HTTP server plus a CLI client anyway.
* **Reason for Rejection**: Rejected by author (2026-11-26), tracked in https://github.com/efsalvarenga/artifice/issues/65: permanent daemon lifecycle and local HTTP plumbing add operational complexity with no advantage over an on-demand CLI wrapper.

### Alternative C: Naming the Tool `omp-sidecar`

* **Pros**: Preserves the initial terminology in https://github.com/efsalvarenga/artifice/issues/65.
* **Cons**: Collides directly with Antigravity's official `sidecar.json` daemon concept and misdescribes an on-demand subprocess dispatcher.
* **Reason for Rejection**: Rejected by author (2026-11-26), tracked in https://github.com/efsalvarenga/artifice/issues/65: renamed to `omp-dispatch`, with an explicit supersession note linking back to https://github.com/efsalvarenga/artifice/issues/65's original wording.

### Alternative D: Allowing `bash` Inside `omp` Under `--approval-mode=yolo` for Code Implementation

* **Pros**: `omp` could execute `unittest` and `./scripts/lint.sh` internally during TDD without sending failure traces back through `agy`.
* **Cons**: Re-introduces an unattended `yolo` shell surface outside `agy`'s terminal sandbox, allowing arbitrary command execution, Git mutation, or bypassing bot provenance if inputs are compromised or misread.
* **Reason for Rejection**: Rejected by author (2026-11-26), tracked in https://github.com/efsalvarenga/artifice/issues/65: restricting `omp` to `--tools=read,grep,glob,edit,write --approval-mode=write` removes the shell attack surface completely, while keeping test and lint execution inside `agy`'s sandbox.

### Alternative E: Reverse Direction (`omp` Calling `agy`, Initial Draft of https://github.com/efsalvarenga/artifice/issues/65)

* **Pros**: Keeps `omp` as the primary session while reaching `agy`'s native EGM plugin.
* **Cons**: Inverts the user's workflow — `agy` is the user's preferred interactive Elephant orchestrator and the objective is offloading heavy Gemini subagent and code-writing spend onto Mistral, not spending Gemini quota from `omp`.
* **Reason for Rejection**: Rejected by author (2026-11-26), tracked in https://github.com/efsalvarenga/artifice/issues/65: reversed to `agy` → `omp` strictly for four bounded workloads, superseding https://github.com/efsalvarenga/artifice/issues/28's wontfix closure for this narrower scope.

### Alternative F: Calling `scripts/mistral_ocr.py`'s `policy_blocks_hosted` Scan Inside `omp-dispatch`

* **Pros**: Reuses [scripts/mistral_ocr.py](../../scripts/mistral_ocr.py)'s existing `policy_blocks_hosted` helper (lines 124–141, invoked at line 159) to refuse hosted Mistral egress automatically if invoked inside a consuming repository carrying `Privacy: on-device` or `Review: local-only`.
* **Cons**: Wires a new caller into gate logic that the maintainer intends to audit and remove across mounted `artifice` skills once cross-project impacts are mapped in https://github.com/efsalvarenga/artifice/issues/66 — mitigated by keeping the refusal default-on and scoping any waiver to a per-invocation, logged flag.
* **Decision (2026-11-27, Round-5 Major 2 adjudicated — accepted in modified form):** `omp-dispatch` runs the `policy_blocks_hosted` upward `AGENTS.md` scan from `<repo_root>` pre-flight on every workload and refuses with `exit 2` (`"error": "privacy_marker_refusal"`) when markers are present, unless `--allow-hosted-egress` is passed for that invocation and logged to `.omp-dispatch-log.jsonl`. The standing waiver https://github.com/efsalvarenga/artifice/issues/66#issuecomment-7214588390 now covers only [skills/review/SKILL.md](../../skills/review/SKILL.md)'s harness-native hosted fan-out (line 38 per-PR human approval preserved) until https://github.com/efsalvarenga/artifice/issues/66 resolves.

### Alternative G: Keeping `skills/review/SKILL.md` at `300 s` With a Separate `600 s` Default in `omp-dispatch`

* **Pros**: Avoids editing line 40 of [skills/review/SKILL.md](../../skills/review/SKILL.md).
* **Cons**: Creates two divergent timeout policies for the same 4-lens review runbook depending on whether lenses run natively or via `omp-dispatch`.
* **Reason for Rejection**: Rejected by author (2026-11-26), tracked in https://github.com/efsalvarenga/artifice/issues/65: raise [skills/review/SKILL.md](../../skills/review/SKILL.md) line 40 to `600 s` so both paths share one timeout policy (mechanically enforced in `omp-dispatch`, harness-bounded natively), while keeping line 36's harness-native spawn default and line 38's per-PR hosted-fan-out approval rule.

### Alternative H: Host-Local Script Installation (`~/.local/bin/omp-dispatch`) Outside `artifice`

* **Pros**: Lives directly on `PATH` without adding scripts, unit tests, or canonical skill files to `artifice`.
* **Cons**: Operates outside version control, `./scripts/lint.sh`, [scripts/install_antigravity.sh](../../scripts/install_antigravity.sh) preflight verification, and canonical `$ARTIFICE_ROOT/scripts/` dispatch paths used by sibling tooling (such as [scripts/mistral_ocr.py](../../scripts/mistral_ocr.py) and callers invoking [scripts/gh-bot](../../scripts/gh-bot), which resolves its physical path internally via `BASH_SOURCE[0]` realpath).
* **Reason for Rejection**: Rejected by author (2026-11-26), tracked in https://github.com/efsalvarenga/artifice/issues/65: keeping `omp-dispatch` inside `artifice` aligns distribution, testing, linting, and `$ARTIFICE_ROOT` invocation parity with existing scripts.

### Alternative I: Truncating or Summarising Review Payloads Instead of `omp` Offload

* **Pros**: Shrinks context sizes fed to native Gemini `invoke_subagent` calls, reducing native review spend without maintaining `scripts/omp_dispatch.py`.
* **Cons**: Lossy truncation or pre-summarisation breaks the verbatim zero-context review guarantee required by [skills/review/SKILL.md](../../skills/review/SKILL.md) and upstream EGM (risking missed defects in omitted diff hunks or specification clauses) and does not cover multi-turn spec-driven code writing (`implement`).
* **Reason for Rejection**: Rejected by author (2026-11-27), tracked in https://github.com/efsalvarenga/artifice/issues/65: preserving verbatim specification, diff, and context inspection requires full inputs on offloaded workloads rather than lossy payload truncation.
